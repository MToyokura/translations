EUの多くの国では、政府による自由ソフトウェアの利用を促進する政策が整備されており、中には2000年代から取り組んでいる国もあります。しかし、これまで行政機関における自由ソフトウェアの導入は限定的でした。その理由の一つは、ソフトウェア・ソリューションに関する公共入札の多くが、自由ソフトウェアの調達に適した形になっていないことです。ここでは、公共調達を自由ソフトウェアに適したものにするための、特に重要な4つのポイントを紹介します。

## ソフトウェア・ライセンスではなく、ソリューションを調達する

入札は、特定の技術や提供形態に偏らないように設計しましょう。特定の商用ソフトウェア製品を指定してしまえば、自由ソフトウェアは対象外になります。入札で「ソフトウェア・ライセンス」の購入を求めても、自由ソフトウェアは除外されます。自由ソフトウェアのライセンスそのものは購入するものではないからです。一方、カスタマイズやカスタマーサポートなどのサービスを入札内容に含めれば、自由ソフトウェア企業も公平な条件で競争できます。これにより、総保有コスト（TCO）に基づいた競争的な比較も可能になります。自由ソフトウェアでは、費用の大部分がサービスに集中します。一方、プロプライエタリ・ソフトウェアでは、基本的なサービス費用がライセンス価格に含まれている場合が多く、単純な比較では条件に偏りが生じます。

## 法的な影響を理解する

EU加盟国の多くでは、自由ソフトウェアを既存の調達制度に当てはめるのが容易ではありません。調達するのは「物品」、つまりソフトウェア・ライセンスでしょうか。それとも、カスタマイズやカスタマーサポートなどの「サービス」でしょうか。これらは多くの場合、別々の手続きとして扱われます。また、無料のものをどのように「調達」するのでしょうか。多くの国では、自由ソフトウェアを公共入札の対象とする方法について、専用のガイドや少なくとも法的な評価文書を提供しています。こうした資料を参照するとともに、自国の自由ソフトウェア関連団体や、すでに自由ソフトウェアを適切に調達した経験を持つ他の公共機関に相談し、法律に適合した入札方法を理解してください。

## 調達要件を緩和する

公共入札への参加では、製品と価格を説明するだけでなく、数多くの手続きをこなさなければならないことがあります。一部の国では、入札に参加する前に企業が登録しなければならない供給事業者リストを設けています。また、入札企業に対して、詳細な事前資格審査の質問票への回答や、セキュリティ、労働、製造基準などに関する多数の証明書の提出を求める場合もあります。自由ソフトウェアは、一般に中小企業によって提供されることが多いため、このような要件を必要最小限に抑え、遵守に必要な支援を提供することで、自由ソフトウェア企業が入札へ参加する際の障壁を下げることができます。

## 自由ソフトウェアの強みを入札条件に含める

入札の評価項目には、自由ソフトウェアが一般的に持つ強みを適切に反映させましょう。たとえば、相互運用性、単一のソフトウェア事業者からの戦略的独立、ベンダーロックインの回避などです。さらに、自由ソフトウェアのライセンスとサービスは、カスタマイズや自らによる追加開発にも有利です。このような要素を入札条件に含めることで、自由ソフトウェアが本来の強みを発揮できるようになります。
